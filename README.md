# 공급망 보안 5주 스터디

제로베이스 학습자가 공통 기술 기초를 준비한 뒤 개발부터 클라우드, 네트워크, AI 공급망으로 범위를 확장하고, 마지막 주에 4개월 프로젝트 주제를 선정하는 과정입니다.

## 왜 이 순서인가?

```text
개발 공급망
  ↓ 만들어진 SW가
클라우드에 빌드·배포되고
  ↓ 산출물과 요청이
네트워크를 통해 이동하며
  ↓ 이 기반 위에 데이터·모델이 추가된
AI 공급망이 구성된다
```

AI 공급망은 코드, 패키지, 클라우드, 네트워크 위에 데이터와 모델이 추가된 구조입니다. 따라서 아래 순서를 따릅니다.

| 주차 | 난이도 | 중심 영역 | 핵심 질문 |
|---|---:|---|---|
| [사전 준비](weeks/week-00-prerequisites/README.md) | ★☆☆☆☆ | Git·터미널·HTTP | 스터디 문서와 실습을 따라갈 기초가 있는가? |
| [1주차](weeks/week-01-development/README.md) | ★★☆☆☆ | 개발 공급망 | 외부 코드가 어떻게 제품에 들어오는가? |
| [2주차](weeks/week-02-cloud/README.md) | ★★★☆☆ | 클라우드 공급망 | 제품은 어떻게 이미지가 되어 배포되는가? |
| [3주차](weeks/week-03-network/README.md) | ★★★☆☆ | 네트워크·배포 공급망 | 산출물은 어떤 경로로 이동하고 검증되는가? |
| [4주차](weeks/week-04-ai/README.md) | ★★★★☆ | AI 공급망 | 데이터와 모델의 출처를 어떻게 신뢰하는가? |
| [5주차](weeks/week-05-integration/README.md) | ★★★★☆ | 통합·주제선정 | 4개월 동안 어떤 공백을 해결할 것인가? |

## 학습 목표

사전 준비와 5주 과정을 마친 뒤 다음을 할 수 있어야 합니다.

- 코드부터 사용자까지 이어지는 공급망을 그릴 수 있다.
- 개발·클라우드·네트워크·AI 영역의 자산과 신뢰 경계를 식별할 수 있다.
- 취약점, 악성 구성요소, 변조, 설정 오류를 구분할 수 있다.
- SBOM, 전자서명, 출처 증명, 접근통제의 역할과 한계를 설명할 수 있다.
- CVSS, EPSS, KEV와 실제 노출 여부를 함께 사용해 조치 우선순위를 판단할 수 있다.
- GitHub 저장소와 CI/CD의 주요 공급망 위험을 설명할 수 있다.
- 실제 문제와 평가 방법이 포함된 4개월 프로젝트 후보를 제안할 수 있다.

## 권장 진행 방식

- 기간: 5주
- 사전 준비: 부족한 항목만 선택해 3~5시간
- 권장 시간: 주 5~7시간
- 비율: 개념 40% + 사례 30% + 실습 30%
- 실제 악성코드를 사용하지 않고, 소유한 로컬·격리 환경에서만 실습합니다.

### 한 주의 진행 예시

| 회차 | 활동 | 권장 시간 |
|---|---|---:|
| 1회차 | 용어와 전체 흐름 이해 | 90분 |
| 2회차 | 대표 사고 분석 | 90분 |
| 3회차 | 안전한 미니 실습 | 120분 |
| 4회차 | 결과 정리와 토론 | 60분 |

## 모든 주차에 적용할 여섯 질문

1. 외부에서 무엇을 가져오는가?
2. 누구와 어떤 시스템을 신뢰하는가?
3. 어디에서 취약점이나 변조가 발생할 수 있는가?
4. 출처와 무결성을 어떻게 확인하는가?
5. 문제가 생기면 영향 범위를 어떻게 파악하는가?
6. 예방·탐지·대응 책임자는 누구인가?

## 매주 제출할 결과물

1. 자신의 말로 작성한 핵심 개념 1쪽
2. 실제 사고 사례 분석 1건
3. 공급망 구조도 또는 위협 흐름도 1개
4. 안전한 미니 실습 기록
5. 아직 답하지 못한 질문 3개
