# 공급망 보안 프레임워크 지도

프레임워크를 조항별로 외우지 말고 어떤 질문에 답하는지 구분합니다.

| 프레임워크·표준 | 핵심 질문 | 이 스터디에서 연결되는 부분 |
|---|---|---|
| NIST CSF | 조직은 위험을 어떻게 식별·보호·탐지·대응·복구하는가? | 전체 위험관리 |
| NIST C-SCRM | 공급자와 전체 생명주기의 위험을 어떻게 관리하는가? | 참여자·제3자 위험 |
| NIST SSDF | 조직은 안전한 SW를 어떻게 개발하고 취약점에 대응하는가? | 1주차·CI/CD |
| SLSA | 빌드 산출물과 출처의 신뢰를 어떻게 높이는가? | 3주차·출처 증명 |
| SPDX | 구성요소와 라이선스 정보를 어떻게 교환하는가? | 5주차·SBOM |
| CycloneDX | 보안 중심의 BOM 정보를 어떻게 표현하는가? | 5주차·SBOM |
| in-toto | 공급망 단계와 검증 규칙을 어떻게 표현하는가? | 3주차·무결성 |
| Sigstore·Cosign | 산출물과 이미지를 어떻게 서명·검증하는가? | 2~3주차 |
| VEX | 제품이 알려진 취약점의 영향을 받는지 어떻게 전달하는가? | 5주차·우선순위 |
| OWASP SCVS | 외부 SW 구성요소를 어떻게 검증하는가? | 1주차·의존성 |

## 기억할 연결

```text
SSDF  → 안전하게 개발하는 조직과 활동
SLSA  → 빌드 과정과 출처의 신뢰
SBOM  → 제품에 포함된 구성요소
VEX   → 특정 취약점의 제품 영향 상태
서명  → 승인 주체와 무결성
C-SCRM → 이 모든 활동을 공급자와 생명주기 전체에서 관리
```

## 사용 방법

프로젝트 주제를 선택한 뒤 관련 프레임워크 1~2개만 골라 요구사항과 평가 기준의 근거로 사용합니다. 프레임워크를 많이 적용하는 것보다 선택한 통제를 실제로 구현하고 효과를 측정하는 것이 중요합니다.
