# 4주차: AI·데이터·모델 공급망

난이도: ★★★★☆

선행지식: 개발 의존성, 클라우드 배포, 네트워크 API

## 이번 주 목표

AI 시스템에서는 코드뿐 아니라 데이터, 모델, 프레임워크, 모델 저장소, 외부 API도 공급망 구성요소라는 점을 이해합니다.

```text
외부 데이터
  ↓
학습 코드·라이브러리 + 사전학습 모델
  ↓
학습·평가
  ↓
모델 저장소
  ↓
클라우드 배포
  ↓
추론 API
```

## 1. 먼저 익힐 기초

- 학습과 추론
- 데이터셋
- 모델과 가중치
- 사전학습 모델
- 파인튜닝
- 모델 허브
- AI 프레임워크
- 추론 API

## 2. 공급망 보안 개념

- 데이터 출처, 라이선스, 오염
- 데이터 포이즈닝과 모델 백도어
- 출처가 불분명한 사전학습 모델
- 모델 파일의 위험한 직렬화 형식
- 모델 허브 계정과 저장소 탈취
- AI 프레임워크와 Python 패키지 의존성
- 외부 AI API와 플러그인 의존성
- 모델 버전·해시·출처 기록
- 모델 카드, 데이터 카드, AI BOM 개념

## 3. 사례 분석

공개 AI 모델 또는 데이터셋 하나를 선택합니다.

- 제작자와 배포 위치는 누구인가?
- 학습 데이터와 라이선스를 확인할 수 있는가?
- 어떤 라이브러리와 실행 코드가 필요한가?
- 파일 형식은 안전한가?
- 누가 변경했고 어떤 평가를 통과했는지 확인할 수 있는가?

## 4. 미니 실습

실제로 실행하지 않고 공개 모델 하나의 메타데이터를 조사해도 됩니다.

1. 모델명, 버전, 제작자, 다운로드 위치를 기록합니다.
2. 파일 형식과 해시 제공 여부를 확인합니다.
3. 모델 카드와 라이선스를 확인합니다.
4. 필요한 프레임워크와 패키지를 목록화합니다.
5. 신뢰 여부를 판단할 체크리스트를 작성합니다.

신뢰할 수 없는 모델 파일은 다운로드하거나 실행하지 않습니다.

## 5. 토론 질문

- 정확도가 높은 모델은 안전한 모델인가?
- 모델 해시가 같으면 학습 데이터도 신뢰할 수 있는가?
- AI BOM은 기존 SBOM에 무엇을 더 기록해야 하는가?
- 외부 AI API를 사용할 때 공급망 책임은 누구에게 있는가?

## 완료 기준

- [ ] AI 생명주기를 공급망으로 표현했다.
- [ ] 코드 취약점과 데이터·모델 위험을 구분했다.
- [ ] 모델 카드와 SBOM의 역할 차이를 설명할 수 있다.
- [ ] 공개 모델 하나를 출처·무결성 관점에서 분석했다.
- [ ] 안전한 모델 도입 체크리스트를 작성했다.
