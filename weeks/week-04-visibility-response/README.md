# 4주차: 가시성, 탐지, 취약점 대응

난이도: 중급

## 이번 주 질문

> 무엇이 포함됐고, 무엇이 실제 사용되며, 무엇부터 고쳐야 하는가?

## 핵심 개념

- 자산 인벤토리와 SBOM
- SPDX, CycloneDX, PURL, CPE
- CVE, CVSS, EPSS, KEV
- 구성요소 존재 여부와 런타임 사용 여부의 차이
- 도달 가능성과 실제 악용 가능성
- 취약점 우선순위화와 예외 관리

## 카테고리별 학습

### 개발

- SBOM 생성 시점: 소스, 빌드, 배포
- 직접·전이 의존성 추적
- SCA 결과의 오탐과 누락
- 취약점 발견부터 패치까지의 처리 흐름

### 클라우드

- 클라우드 자산과 컨테이너 이미지 인벤토리
- 실제 배포된 이미지와 빌드 당시 목록 비교
- 로그와 런타임 관측을 이용한 사용 여부 확인
- 취약 워크로드의 노출 범위 판단

### AI

- 데이터·모델·프레임워크 정보를 담는 AI BOM 개념
- 모델 카드 및 데이터 카드와 SBOM의 차이
- 모델 버전, 평가 결과, 배포 위치 연결
- 외부 모델 취약점·라이선스·안전성 정보 관리

### 네트워크

- 자산 노출 여부와 통신 흐름 확인
- 취약 구성요소가 외부 요청을 받는지 판단
- DNS, 프록시, 방화벽, 흐름 로그를 통한 가시성
- 사고 시 차단, 격리, 패치, 복구 순서

## 미니 실습

작은 예제 프로젝트에서 의존성 목록을 확인하고 다음 표를 작성합니다.

| 구성요소 | 버전 | 직접/전이 | 운영 포함 | 외부 노출 | 알려진 취약점 | 조치 |
|---|---|---|---|---|---|---|

도구 결과를 그대로 받아들이지 말고 이름, 버전, 경로가 맞는지 수동으로 표본 검증합니다.

## 완료 기준

- [ ] SBOM이 보장하는 것과 보장하지 않는 것을 구분했다.
- [ ] CVSS만으로 우선순위를 정하면 안 되는 이유를 설명했다.
- [ ] 포함·실행·도달 가능성의 차이를 설명했다.
- [ ] 취약점 대응 흐름과 담당자를 정의했다.
