# 1주차: 공급망 보안 전체 지도

난이도: 입문

## 이번 주 질문

> 하나의 디지털 서비스가 만들어져 사용자에게 전달되기까지 누구와 무엇을 신뢰하는가?

## 핵심 개념

- 전통적 공급망과 SW 공급망의 차이
- 개발사, 공급사, 운영사, 외부 협력사의 역할
- SDLC: 설계, 개발, 빌드, 배포, 운영, 업데이트, 폐기
- 자산, 위협, 취약점, 위험, 통제의 차이
- 직접 의존성과 전이 의존성
- 신뢰 경계와 공동책임

## 카테고리별 학습

### 개발

- 소스코드가 패키지와 빌드를 거쳐 실행 파일이 되는 과정
- Git 저장소, 패키지 관리자, CI/CD의 역할
- 직접 설치한 패키지와 하위 의존성의 차이

### 클라우드

- 클라우드 사업자와 사용자의 공동책임 모델
- 계정, 이미지, 비밀정보, 서비스 설정이 공급망에 포함되는 이유
- SaaS, PaaS, IaaS에서 통제 범위가 달라지는 이유

### AI

- 데이터 수집, 학습, 모델 저장, 배포, 추론으로 이어지는 AI 생명주기
- 외부 데이터셋, 사전학습 모델, 라이브러리, API 의존성
- 일반 SW 공급망과 AI 공급망의 공통점과 차이

### 네트워크

- 개발자부터 최종 사용자까지 데이터와 산출물이 이동하는 경로
- 인터넷, 사내망, 클라우드, 저장소 사이의 신뢰 경계
- DNS, TLS, 프록시, 방화벽의 기본 역할

## 사례 학습

Log4Shell을 다음 질문으로 분석합니다.

1. 최초 문제는 어디에 있었는가?
2. 어떤 제품으로 전파됐는가?
3. 조직은 왜 포함 여부를 바로 알지 못했는가?
4. 예방, 탐지, 대응 중 무엇이 부족했는가?

## 미니 실습

자주 사용하는 애플리케이션 하나를 선택해 공급망 지도를 그립니다.

```text
개발자 → 저장소 → 외부 패키지 → 빌드 → 클라우드 → 네트워크 → 사용자
```

각 단계에 자산, 책임자, 외부 의존성, 신뢰 경계를 하나 이상 표시합니다.

- [ ] Log4Shell 사례를 5문장으로 정리했다.
- [ ] 가장 관심 있는 공급망 단계 2개를 골랐다.
