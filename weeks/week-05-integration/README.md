# 5주차: 통합 위협모델과 프로젝트 주제선정

난이도: ★★★★☆

선행지식: 1~4주차

## 이번 주 목표

개발, 클라우드, 네트워크, AI 공급망을 하나의 시스템으로 연결하고, 4개월 프로젝트에서 해결할 현실적인 문제를 선정합니다.

## 1. 통합 구조

```text
개발자
→ Git 저장소
→ 외부 패키지·AI 모델·데이터
→ 클라우드 CI/CD
→ 컨테이너 레지스트리
→ 네트워크 배포
→ 운영환경
→ 추론 API·사용자
```

## 2. 위협모델 작성

다음 순서로 작성합니다.

1. 보호할 자산
2. 참여자와 책임
3. 외부에서 가져오는 구성요소
4. 데이터·산출물 흐름
5. 신뢰 경계
6. 공격자와 공격 목표
7. 가능한 공격 경로
8. 현재 예방·탐지·대응 통제
9. 해결되지 않은 위험

## 3. 영역별 연결 확인

| 영역 | 확인할 대상 | 대표 위험 |
|---|---|---|
| 개발 | 코드, 패키지, 빌드 | 악성 의존성, 저장소·빌드 변조 |
| 클라우드 | 이미지, IAM, 레지스트리 | 권한 탈취, 이미지 바꿔치기 |
| 네트워크 | 저장소·배포·업데이트 경로 | 가로채기, 신뢰 채널 악용 |
| AI | 데이터, 모델, 프레임워크 | 데이터 오염, 모델·파일 변조 |

## 4. 프로젝트 후보 예시

### 후보 A: SBOM 품질 검증

- 문제: 도구마다 누락·중복·버전 오류가 발생
- 평가: 정확도, 누락률, 중복률, 분석시간

### 후보 B: 런타임 기반 취약점 우선순위화

- 문제: 제품에 포함된 패키지와 실제 사용되는 패키지를 구분하기 어려움
- 평가: 경고 감소율, 실제 사용 구성요소 식별률

### 후보 C: 빌드·배포 산출물 출처 검증

- 문제: 정상 소스가 빌드, 이미지 저장, 배포 과정에서 변조될 수 있음
- 평가: 변조 탐지율, 검증시간, 차단 성공률

### 후보 D: AI 모델 도입 위험평가

- 문제: 외부 모델의 출처, 파일 안전성, 라이선스, 평가정보가 분리돼 있음
- 평가: 위험 모델 식별률, 검사시간, 판단 근거의 설명 가능성

### 후보 E: 공급망 통합 인벤토리

- 문제: 코드, 이미지, 클라우드 자산, 모델의 소유자와 배포 위치가 연결되지 않음
- 평가: 자산 식별률, 변경 추적률, 영향 분석시간

## 5. 후보 평가 기준

각 항목을 1~5점으로 평가합니다.

| 기준 | 확인할 질문 |
|---|---|
| 현실성 | 실제 현장에서 반복되는 문제인가? |
| 구현 가능성 | 4개월 안에 핵심 기능을 완성할 수 있는가? |
| 데이터 확보 | 안전한 실험 자료를 구할 수 있는가? |
| 측정 가능성 | 전후 효과를 숫자로 평가할 수 있는가? |
| 차별성 | 기존 도구가 해결하지 못한 공백이 있는가? |
| 시연 가능성 | 공격과 방어를 안전하게 보여줄 수 있는가? |
| 관심도 | 팀이 4개월 동안 몰입할 수 있는가? |

## 6. 프로젝트 범위 정하기

좋은 문제정의:

> 특정 사용자가 특정 과정에서 겪는 공급망 문제를, 정해진 환경과 데이터로 탐지·완화하고, 효과를 수치로 평가한다.

너무 넓은 문제정의:

> AI를 사용하여 모든 공급망 공격을 탐지한다.

반드시 포함할 항목:

- 해결할 사용자와 문제
- 보호할 자산
- 공격 또는 실패 시나리오
- 기존 방법과 한계
- 구현할 기능
- 구현하지 않을 범위
- 평가 지표
- 안전하고 윤리적인 실험 방법
