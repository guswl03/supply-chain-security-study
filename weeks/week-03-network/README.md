# 3주차: 네트워크·배포 공급망

난이도: ★★★☆☆

선행지식: 1~2주차의 저장소, 빌드, 클라우드 배포

## 이번 주 목표

패키지, 이미지, 업데이트가 이동하는 경로와 각 경로의 신뢰 경계를 이해합니다. 네트워크 전체가 아니라 공급망에 필요한 범위만 학습합니다.

```text
개발자 → 패키지 저장소 → 빌드 서버 → 배포 서버 → 업데이트 서버 → 사용자
```

## 1. 먼저 익힐 기초

- IP 주소와 포트
- 클라이언트와 서버
- DNS
- HTTP와 HTTPS
- TLS와 인증서
- 방화벽, 프록시, VPN
- 내부망과 외부망
- 요청, 응답, 로그

## 2. 공급망 보안 개념

- 패키지 다운로드 경로와 저장소 미러
- 업데이트 서버 및 배포 채널
- DNS·라우팅·프록시 변조 위험
- 인증서 검증과 전자서명의 역할 차이
- 협력사 원격접속 경로
- 개발망·빌드망·운영망 분리
- 허용된 저장소와 송신 목적지 제한
- 네트워크 로그를 통한 이상행위 탐지

## 3. 사례 분석

### 필수: SolarWinds

- 왜 공식 업데이트가 공격 경로가 됐는가?
- 네트워크 암호화만으로 막을 수 있었는가?
- 고객은 정상 업데이트와 악성 업데이트를 어떻게 구분할 수 있었는가?

### 선택: Kaseya 또는 3CX

연쇄 전파가 어느 신뢰 관계를 따라 발생했는지 그립니다.

## 4. 미니 실습

1. 개발자부터 사용자까지 산출물 이동 경로를 그립니다.
2. 각 연결에 프로토콜, 인증 주체, 신뢰 근거를 표시합니다.
3. 가로채기, 서버 탈취, 계정 탈취 시나리오를 각각 하나씩 추가합니다.
4. 예방, 탐지, 대응 통제를 하나 이상 매핑합니다.

실제 트래픽 가로채기나 타인의 시스템 대상 실습은 수행하지 않습니다.

## 5. 토론 질문

- HTTPS면 다운로드한 파일을 무조건 신뢰할 수 있는가?
- 파일 서명과 TLS는 각각 무엇을 보호하는가?
- 협력사 VPN은 왜 중요한 공급망 공격 경로가 되는가?
- 정상적인 업데이트 트래픽과 공격을 어떻게 구분할 수 있는가?

## 완료 기준

- [ ] DNS, HTTPS, TLS의 역할을 간단히 설명할 수 있다.
- [ ] 네트워크 암호화와 산출물 서명의 차이를 설명할 수 있다.
- [ ] 배포 경로의 신뢰 경계를 표시했다.
- [ ] 공급망 사고의 연쇄 전파 경로를 분석했다.
- [ ] 예방·탐지·대응 통제를 구분했다.
