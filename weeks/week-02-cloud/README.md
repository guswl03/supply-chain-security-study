# 2주차: 클라우드·컨테이너 공급망

난이도: ★★★☆☆

선행지식: 1주차의 패키지, 빌드, CI/CD

## 이번 주 목표

개발된 프로그램이 컨테이너 이미지가 되어 저장되고 클라우드에 배포되는 흐름을 이해합니다.

```text
소스코드 → 클라우드 빌드 → 컨테이너 이미지 → 레지스트리 → 클라우드 배포
```

## 1. 먼저 익힐 기초

- 서버와 클라우드
- IaaS, PaaS, SaaS
- 클라우드 공동책임 모델
- 가상머신과 컨테이너의 차이
- 이미지, 컨테이너, 레지스트리
- 계정, 역할, 권한, IAM
- 환경변수, API 키, 비밀정보

## 2. 공급망 보안 개념

- 외부 베이스 이미지 위험
- 공개·사설 이미지 레지스트리
- 이미지 태그와 변경 불가능한 다이제스트
- 클라우드 CI/CD 자격증명 탈취
- 과도한 IAM 권한
- 외부 IaC 모듈과 공급자 의존성
- 이미지 서명과 배포 전 검증
- 격리된 빌드 환경

## 3. 사례 분석

클라우드 또는 컨테이너 관련 사고 하나를 선택해 다음을 확인합니다.

- 최초 침해된 계정·이미지·서비스는 무엇인가?
- 장기 자격증명이나 과도한 권한이 있었는가?
- 빌드와 운영 환경이 적절히 분리됐는가?
- 변조된 이미지가 배포되는 것을 어떻게 막을 수 있었는가?

## 4. 미니 실습

1주차 예제 프로젝트를 컨테이너 이미지로 만든다고 가정하거나 실제로 빌드합니다.

1. 베이스 이미지의 이름과 출처를 확인합니다.
2. 이미지 태그와 다이제스트의 차이를 확인합니다.
3. 이미지 내부 구성요소를 목록화합니다.
4. 소스 단계 목록과 이미지 단계 목록의 차이를 비교합니다.
5. 개발자, 빌드 서비스, 레지스트리, 운영환경의 권한을 표로 작성합니다.

## 5. 토론 질문

- 공식 이미지는 항상 신뢰할 수 있는가?
- `latest` 태그를 고정해서 사용하면 어떤 문제가 생기는가?
- 클라우드 사업자와 사용자는 각각 무엇을 보호해야 하는가?
- 서명된 이미지가 취약하지 않다는 뜻인가?

## 완료 기준

- [ ] 공동책임 모델을 설명할 수 있다.
- [ ] 이미지와 실행 중인 컨테이너를 구분할 수 있다.
- [ ] 태그와 다이제스트의 차이를 설명할 수 있다.
- [ ] 빌드부터 클라우드 배포까지의 공급망을 그렸다.
- [ ] 계정·권한·비밀정보 위험을 식별했다.

## 다음 주 연결

클라우드에 저장된 이미지와 업데이트는 네트워크 경로를 통해 이동합니다. 다음 주에는 이 이동 경로의 신뢰와 검증을 다룹니다.
