# 사전 준비: 프로젝트를 따라가기 위한 공통 기초

난이도: ★☆☆☆☆

이 과정은 정규 5주차에 포함하지 않습니다. 이미 아는 항목은 건너뛰고, 체크하지 못한 부분만 학습합니다.

## 목표

공급망 보안 도구와 문서를 이해하기 위한 최소한의 개발·통신 기초를 준비합니다.

## 1. 터미널과 파일

- 현재 경로와 파일 경로
- 파일·폴더 목록 확인
- 프로그램 실행과 종료 코드
- 환경변수
- 설정 파일과 로그 읽기
- 비밀정보를 터미널 기록과 Git에 남기지 않는 방법

완료 기준:

- [ ] 프로젝트 폴더로 이동해 파일 목록을 확인할 수 있다.
- [ ] 명령 성공과 실패를 종료 코드 또는 메시지로 구분할 수 있다.
- [ ] 환경변수와 일반 파일의 차이를 설명할 수 있다.

## 2. Git과 GitHub

- 저장소, 커밋, 브랜치, 원격 저장소
- `clone`, `status`, `add`, `commit`, `push`, `pull`
- Pull Request와 코드 리뷰
- 병합 충돌의 의미
- `.gitignore`
- 브랜치 보호와 승인 규칙

안전한 연습 흐름:

```text
저장소 복제
→ 새 브랜치
→ 문서 수정
→ 변경 확인
→ 커밋
→ 원격 브랜치 업로드
→ Pull Request
→ 리뷰 후 병합
```

완료 기준:

- [ ] 브랜치와 커밋의 차이를 설명할 수 있다.
- [ ] PR이 공급망 보안 통제에 해당하는 이유를 설명할 수 있다.
- [ ] 저장소에 비밀번호와 API 키를 올리면 안 되는 이유를 설명할 수 있다.

## 3. 데이터 형식

- JSON의 객체, 배열, 키, 값
- YAML의 들여쓰기와 목록
- Markdown의 제목, 링크, 코드 블록
- 설정 파일 변경도 코드 변경과 같이 검토해야 하는 이유

완료 기준:

- [ ] 간단한 JSON과 YAML 파일을 읽을 수 있다.
- [ ] YAML 들여쓰기 오류가 자동화 과정에 미칠 영향을 설명할 수 있다.

## 4. HTTP와 API

- 클라이언트와 서버
- URL, 도메인, 경로, 쿼리
- 요청 메서드: GET, POST, PUT/PATCH, DELETE
- 요청 헤더와 본문
- 상태 코드: 2xx, 4xx, 5xx
- 인증과 인가
- API 키, 액세스 토큰, 세션

완료 기준:

- [ ] API 요청과 응답 흐름을 그릴 수 있다.
- [ ] 인증과 인가의 차이를 설명할 수 있다.
- [ ] API 키가 유출됐을 때 필요한 대응을 말할 수 있다.

## 5. 보안 기본 개념

- 자산, 위협, 취약점, 위험, 통제
- 기밀성, 무결성, 가용성
- 최소 권한
- 해시, 암호화, 전자서명의 차이
- 예방, 탐지, 대응

완료 기준:

- [ ] 파일 해시가 암호화가 아닌 이유를 설명할 수 있다.
- [ ] 하나의 위험에 예방·탐지·대응 통제를 각각 제안할 수 있다.

## 사전 준비 종료 조건

아래 흐름을 자신의 말로 설명하면 1주차로 이동합니다.

```text
개발자가 Git 브랜치에 코드를 올리고
→ PR 리뷰를 거쳐 병합하고
→ 자동화 시스템이 JSON·YAML 설정을 읽어 빌드하며
→ 프로그램이 외부 API와 통신한다
```
